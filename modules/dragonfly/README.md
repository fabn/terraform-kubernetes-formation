# `dragonfly` addon

Operator-backed Dragonfly (Redis/Valkey-compatible) — a drop-in swap for the
Bitnami [`redis`](../redis) addon (same `REDIS_URL` contract). Master + replica(s)
with operator-managed automatic failover behind a stable `<name>` Service (so the
app needs no sentinel awareness), optional password auth (Terraform-owned) and
optional S3 snapshots (keyless via EKS Pod Identity / IRSA).

**Requires** the Dragonfly operator installed cluster-wide.

## Contract

| Output | Vars |
| --- | --- |
| `env` | `REDIS_URL` — only when `auth = false` |
| `sensitive_env` | `REDIS_URL` — when `auth = true` (the default), the URL carries the password |
| `host`, `service_account_name` | Service hostname, created ServiceAccount |

The variable name is configurable (`url_env_var`), so a second, dedicated cache
instance can emit e.g. `REDIS_CACHE_URL` next to a primary Redis without the two
colliding.

## Usage

```hcl
# A cache: evicts LRU at maxmemory instead of rejecting writes, no HA, no persistence.
module "cache" {
  source  = "fabn/formation/kubernetes//modules/dragonfly"
  version = "~> 0.1"

  namespace   = "myapp-production"
  name        = "cache"
  url_env_var = "REDIS_CACHE_URL"

  cache_mode          = true
  replicas            = 1
  memory_mib          = 1024
  memory_requests_mib = 128
}

# A queue/state store: HA master + replica, snapshots to S3.
module "redis" {
  source  = "fabn/formation/kubernetes//modules/dragonfly"
  version = "~> 0.1"

  namespace = "myapp-production"
  replicas  = 2

  # Keep the master off Spot: a reclaim costs a failover and, with no snapshot,
  # the whole dataset.
  node_affinity = {
    required = [{ key = "karpenter.sh/capacity-type", operator = "In", values = ["on-demand"] }]
  }

  service_account_name = "myapp-dragonfly"
  snapshot             = { s3_uri = "s3://acme-backups/myapp/dragonfly", cron = "0 */6 * * *" }
}
```

See also [`examples/dragonfly`](../../examples/dragonfly).

## Inputs

| Name | Default | Description |
| --- | --- | --- |
| `namespace` | — | Namespace the `Dragonfly` CR is created in |
| `name` | `dragonfly` | CR name; clients connect to the `<name>` Service (repointed to the master on failover) |
| `replicas` | `2` | Total instances. `2` = master + replica with automatic failover; `1` = single instance, no HA |
| `image` | `null` | Dragonfly image; `null` uses the operator default |
| `threads` | `1` | `--proactor_threads`. Raise (with memory) for throughput |
| `memory_mib` | `512` | Pod memory **limit** in MiB. Must be `>= threads × 320` (see below) |
| `memory_requests_mib` | `null` | Pod memory **request** in MiB; `null` pins it to `memory_mib`. Can be far lower than the limit |
| `cpu_requests` | `100m` | CPU request |
| `cache_mode` | `false` | Run as a cache: `--cache_mode` evicts LRU keys at maxmemory instead of rejecting writes with OOM |
| `auth` | `true` | Password auth, password generated by Terraform and handed to the operator through a Secret |
| `url_env_var` | `REDIS_URL` | Name of the emitted connection-URL variable |
| `snapshot` | `null` | Periodic snapshots: exactly one of `s3_uri` (keyless) or `pvc_size`, plus `cron` |
| `service_account_name` | `null` | ServiceAccount for the instance pods (created here); needed for keyless S3 snapshots |
| `service_account_annotations` | `{}` | e.g. the IRSA `eks.amazonaws.com/role-arn` |
| `labels`, `annotations` | `{}`, `{}` | Metadata propagated to the operator's objects |
| `wait_for_ready`, `ready_timeout` | `false`, `6m` | Block the apply until the operator reports the instance Ready |

### HA & placement

| Name | Default | Description |
| --- | --- | --- |
| `node_affinity` | `null` | Set-based placement: `required` + `preferred` match expressions, same shape as a formation web process and as [`postgres-cnpg`](../postgres-cnpg). Rendered into `spec.affinity.nodeAffinity` |
| `node_selector` | `{}` | Exact-match labels |
| `tolerations` | `[]` | Tolerations for the instance pods |
| `topology_spread_constraints` | `[]` | Spread master/replica across nodes or zones |
| `pod_disruption_budget` | `null` | Override the PDB the operator creates on its own (`spec.pdb`): exactly one of `min_available` / `max_unavailable`, absolute (`"1"`) or percentage (`"50%"`) |

#### Production block

The defaults are tuned for a stack that also has to run on a single-node dev
cluster, so production needs an explicit block. This is it, whole — paste it and
adjust. Which one you want depends on what the instance *is*: a queue/state store
(below) or a disposable cache, where `replicas = 1` + `cache_mode = true` is the
right production answer and none of this applies.

```hcl
replicas = 2 # default, but it is what makes failover possible

# Hard spread per node: the operator sets no anti-affinity, so spreading is
# entirely up to these constraints.
topology_spread_constraints = [{
  maxSkew           = 1
  topologyKey       = "kubernetes.io/hostname"
  whenUnsatisfiable = "DoNotSchedule" # ScheduleAnyway on a single-node cluster
  }, {
  maxSkew           = 1
  topologyKey       = "topology.kubernetes.io/zone"
  whenUnsatisfiable = "ScheduleAnyway"
}]

# Keeping the master off Spot is worth more here than for a database: a reclaim
# costs a failover and, with no snapshot, the whole dataset.
node_affinity = {
  required  = [{ key = "karpenter.sh/capacity-type", operator = "In", values = ["on-demand"] }]
  preferred = [{ weight = 100, key = "kubernetes.io/arch", operator = "In", values = ["arm64"] }]
}

# Persistence, keyless to S3 via Pod Identity / IRSA. A cache leaves this null.
service_account_name = "myapp-dragonfly"
snapshot             = { s3_uri = "s3://acme-backups/myapp/dragonfly" }
```

Already right by default, so absent above: the disruption budget (the operator
creates one, `maxUnavailable = 1`) and `auth`. Deliberately not defaulted, because
each needs something only you know: `DoNotSchedule` leaves the replica `Pending` on
a single node, the zone label key exists only on a multi-zone cluster,
`karpenter.sh/capacity-type` assumes Karpenter, and the snapshot needs a bucket.
Size the instance (`memory_mib`, `threads`) separately — placement says nothing
about capacity.

`node_affinity` is rendered into the CR's `spec.affinity`, which the operator
copies verbatim onto the StatefulSet pod template; the operator sets no affinity of
its own, so nothing is clobbered. Spreading stays on
`topology_spread_constraints` — anti-affinity needs at least as many nodes as
replicas, or the replica stays `Pending`.

**Disruption budget.** The operator already creates a PodDisruptionBudget for any
instance with more than one replica, defaulting to `maxUnavailable = 1` (and none at
all at `replicas = 1`, where there is nothing to protect). `pod_disruption_budget`
only customises that budget — the useful case being a 3+ replica instance where
"one at a time" is more conservative than necessary:

```hcl
replicas              = 3
pod_disruption_budget = { min_available = "2" }
```

Exactly one of the two keys may be set: the CRD enforces it with a CEL rule, and
the module validates it at plan time so the failure isn't deferred to the apply.
Both keys still reach the manifest, the unused one as `null` — `kubernetes_manifest`
types the object from the CRD schema and requires every attribute, the same
constraint that forces both `inheritedMetadata` keys in
[`postgres-cnpg`](../postgres-cnpg) — and the API server treats that null as an
absent key, so the mutual-exclusion rule stays satisfied.

## Notes

**Memory floor.** Dragonfly needs `maxmemory >= 256Mi` per io-thread and, when
`maxmemory` is not set explicitly, auto-sets it to 80% of the cgroup limit. So the
memory **limit** must be `>= threads × 320Mi` (0.8 × 320 = 256) or the process
exits at boot ("There are N threads, so …MiB are required. Exiting"). The floor is
on the limit, not the request — hence `memory_requests_mib`, which lets a light
instance reserve little scheduling capacity while still getting the limit Dragonfly
demands. Both constraints are validated.

**Reserved labels.** The operator hardcodes its selector labels (`app`,
`app.kubernetes.io/{name,instance,component,managed-by,version,part-of}`) onto
everything it creates, so they must never reach `spec.labels` — a user value
diverges the pod template from the immutable StatefulSet selector and the operator
fails with "failed to generate dragonfly resources". This module strips them from
the propagated labels. In particular `app.kubernetes.io/part-of` is forced to
`dragonfly`, so `part_of` cannot be honoured on the operator's objects; it still
labels this module's own Secret/ServiceAccount.

**Persistence.** Off by default (`snapshot = null`), which is what a cache wants:
`cache_mode` evicts, and evictable data has no business on disk. Set `snapshot` for
a queue/state store.
